## 왜 필요한가

01~22번 레슨의 개념은 따로 떨어져 있지 않다. 실제 성능 문제는 Iron Law, cache, TLB, SIMD, roofline이 한꺼번에 얽혀서 나온다. 이 레슨은 계산 문제 위주로 Part A 전체를 점검한다. 계산기와 종이를 준비하자.

<Aside type="tip" title="푸는 순서">
객관식은 먼저 손으로 계산하고 보기를 고르자. 서술형은 풀이를 펼치기 전에 끝까지 직접 풀어보는 게 핵심이다. 틀린 문제는 문제 앞에 적힌 레슨 번호로 돌아가 복습하자.
</Aside>

## 서술형

### 문제 1. Edge CNN 최적화 계획

관련 레슨: 02, 03, 21, 22번 레슨

edge 기기: peak 50 GFLOP/s, 메모리 대역폭 10 GB/s. CNN inference 한 번은 다음으로 구성된다.

- Layer A: dense conv, 200 MFLOPs, AI = 40
- Layer B: depthwise conv, 4 MFLOPs, AI = 2
- 기타 연산(전처리, softmax, 데이터 복사): 항상 2 ms

(a) roofline으로 각 레이어의 최소 시간을 구하고, 전체 시간과 병목을 밝혀라.

(b) INT8 quantization을 하면 conv의 peak가 200 GOP/s가 되고(SIMD lane 4배) 각 레이어의 bytes가 1/4이 된다고 하자. 새 시간과 전체 speedup은?

(c) (b) 이후 다음 최적화 대상은 무엇이고, 그 이유는?

<details>
<summary>풀이 보기</summary>

**(a)** ridge point = 50 / 10 = 5 FLOP/B.

- Layer A: AI 40, ridge보다 크므로 compute-bound → $200\text{M} / 50\text{G} = 4$ ms
- Layer B: AI 2, memory-bound → 상한 $10 \times 2 = 20$ GF/s → $4\text{M} / 20\text{G} = 0.2$ ms
- 기타: 2 ms
- 합계 **6.2 ms**. 병목은 Layer A (전체의 65%).

**(b)** 새 ridge point = 200 / 10 = 20. bytes가 1/4이므로 AI는 4배.

- Layer A: AI 160, compute-bound → $200\text{M} / 200\text{G} = 1$ ms
- Layer B: AI 8, 여전히 memory-bound → $10 \times 8 = 80$ GF/s → $4\text{M} / 80\text{G} = 0.05$ ms
- 기타: 2 ms (그대로)
- 합계 **3.05 ms**, speedup = $6.2 / 3.05 \approx$ **2.03배**

**(c)** 이제 기타 연산 2 ms가 전체의 **66%**다 (Amdahl). conv를 아무리 더 가속해도 상한은 $6.2 / 2 = 3.1$배다. 다음 대상은 전처리/softmax/복사다. fusion으로 데이터 복사를 없애거나, 전처리를 가속기로 옮기는 것을 검토한다.

</details>

### 문제 2. 두 배열의 conflict

관련 레슨: 08, 09번 레슨

16 KB **direct-mapped** cache, line 64 B. float 배열 `a`가 주소 0x0000, `b`가 0x4000에서 시작하고 각각 4096개 원소(16 KB)다. 루프 `s += a[i] * b[i]`를 i = 0..4095로 돈다.

(a) a[i]와 b[i]의 index를 비교하라. miss rate는?

(b) 2-way set-associative로 바꾸면 miss rate는?

(c) cache 구조를 바꾸지 않고 해결하는 방법은?

<details>
<summary>풀이 보기</summary>

**(a)** set 수 = 16384 / 64 = 256 → index 8 bit, offset 6 bit. 0x4000 = 16384는 cache 크기와 정확히 같으므로 a[i]와 b[i]의 주소는 bit 14에서만 다르다. index는 bit 6~13이라 **항상 같다.** a[i]를 읽으면 b[i]가 쫓아내고, b[i]를 읽으면 a[i]가 쫓아낸다. 같은 line을 다시 읽을 때마다 miss → **miss rate 100%**, 전부 conflict miss(첫 접근 제외).

**(b)** 2-way면 같은 set에 두 line이 들어가므로 a와 b의 line이 공존한다. line당 float 16개 → **miss rate = 1/16 ≈ 6.25%** (전부 compulsory).

**(c)** `b`의 시작 주소를 line 하나(64 B) 이상 밀어서 padding한다 (예: 0x4040). 그러면 a[i]와 b[i]의 index가 1씩 어긋나서 서로 다른 set으로 간다. 2의 거듭제곱 간격을 피하는 게 핵심이다.

</details>

### 문제 3. 큰 행렬의 column 순회와 huge page

관련 레슨: 10, 15번 레슨

8192 × 8192 float32 행렬(256 MB)을 **column 방향**으로 끝까지 순회한다. TLB는 64 entry, fully associative LRU.

(a) 4 KB page일 때 TLB miss rate는?

(b) 2 MB huge page로 바꾸면 TLB miss rate는? (column 하나를 도는 동안 몇 개의 page를 건드리는지 먼저 세라.)

(c) 근본적인 해결책은?

<details>
<summary>풀이 보기</summary>

**(a)** 행 하나 = 8192 × 4 B = 32 KB = 4 KB page 8개. column 방향 다음 원소는 32 KB 뒤이므로 **매 접근이 다른 page**다. column 하나에 page 8192개를 건드리고 64 entry로는 하나도 남지 않는다 → **miss rate ≈ 100%**.

**(b)** 2 MB page 하나에 행 $2\text{ MB} / 32\text{ KB} = 64$개가 들어간다. column 하나 = 8192행 = page **128개**. 128개는 TLB 64 entry보다 많아서 다음 column을 시작할 때 앞쪽 page들은 이미 쫓겨났다. 하지만 한 page 안에서 연속된 64행은 hit다. → page마다 1 miss + 63 hit → **miss rate = 1/64 ≈ 1.6%**. huge page만으로 64배 개선되지만 0은 아니다.

**(c)** 접근 순서를 row 방향으로 바꾸거나(행렬을 전치해서 저장), tiling으로 몇 개 column씩 묶어서 처리해 working set을 TLB reach와 cache 안에 넣는다. cache miss와 TLB miss가 동시에 해결된다.

</details>
