## 왜 필요한가

엣지 디바이스에서 LLM을 돌릴 때 병목은 보통 **연산량이 아니라 메모리 용량과 메모리 대역폭**임.

- 7B 모델 weight를 FP16으로 저장하면 $7 \times 10^9 \times 2\text{B} \approx 14\text{GB}$ → 폰이나 Jetson에는 안 들어감
- 같은 모델을 INT4로 저장하면 $\approx 3.5\text{GB}$ (+ scale 값 같은 부가 데이터 조금)
- decode 단계에서는 토큰 하나 만들 때마다 weight를 전부 한 번씩 읽어야 함 → **weight가 작을수록 그만큼 빨라짐** (memory-bound)

## Affine (asymmetric) quantization

실수 $x$를 $b$-bit 정수 $q$로 매핑하는 방식:

$$
q = \text{clamp}\left(\left\lfloor \frac{x}{s} \right\rceil + z,\ 0,\ 2^b - 1\right), \qquad \hat{x} = s\,(q - z)
$$

- $s$ (scale) $= \dfrac{x_{\max} - x_{\min}}{2^b - 1}$
- $z$ (zero-point) $= \left\lfloor -\dfrac{x_{\min}}{s} \right\rceil$
- $\hat{x}$와 $x$의 차이가 **quantization error**임

**Symmetric** 방식은 $z = 0$으로 고정하고 $s = \dfrac{\max|x|}{2^{b-1}-1}$로 둠. 계산이 단순해서 weight에 많이 씀. 다만 분포가 한쪽으로 치우쳐 있으면 표현 범위를 낭비함.

```python
import numpy as np

def quantize(x, bits=4):
    qmax = 2**bits - 1
    s = (x.max() - x.min()) / qmax
    z = np.round(-x.min() / s)
    q = np.clip(np.round(x / s) + z, 0, qmax).astype(np.uint8)
    return q, s, z

def dequantize(q, s, z):
    return s * (q.astype(np.float32) - z)

w = np.random.randn(4096).astype(np.float32)
q, s, z = quantize(w, bits=4)
print("MSE:", np.mean((w - dequantize(q, s, z))**2))
```

## Granularity: scale을 어느 단위로 잡을까

| 방식 | scale 개수 | 정확도 | 비고 |
|---|---|---|---|
| per-tensor | 텐서당 1개 | 낮음 | outlier 하나에 전체 범위가 끌려감 |
| per-channel | output channel당 1개 | 중간 | CNN이나 INT8에서 표준 |
| per-group (예: g=128) | 128개 weight당 1개 | 높음 | **LLM INT4의 사실상 표준** |

group size가 작을수록 정확도는 올라가지만 scale 저장 overhead가 늘어남. g=128이고 scale이 FP16이면 weight 하나당 대략 +0.125bit.

## Outlier 문제

LLM **activation**에는 크기가 다른 값보다 수십 배 큰 outlier channel이 있음. 그래서 activation까지 INT8로 그냥 양자화하면 성능이 무너짐.

- **LLM.int8()**: outlier channel만 따로 떼서 FP16으로 계산함
- **SmoothQuant**: activation의 스케일 일부를 weight 쪽으로 옮겨서 activation 분포를 평평하게 만듦
- 그래서 엣지에서는 **weight-only quantization** (W4A16)이 흔함. weight는 INT4로 저장하고, 계산 직전에 FP16으로 dequant해서 연산함

## PTQ vs QAT

- **PTQ (Post-Training Quantization)**: 학습이 끝난 모델에 calibration 데이터 조금만 넣어서 양자화함. 싸고 빠름. GPTQ와 AWQ가 여기 속함
  - **GPTQ**: 2차 정보(Hessian)를 써서, weight 하나를 양자화할 때 생긴 오차를 아직 양자화 안 한 weight들이 보정하도록 업데이트함
  - **AWQ**: activation 크기 기준으로 중요한 weight channel 약 1%를 찾아서, 스케일링으로 그 channel들을 보호함
- **QAT (Quantization-Aware Training)**: 학습 중에 fake-quant를 넣어서 모델이 양자화 오차에 적응하게 함. 정확도는 가장 좋지만 LLM에서는 비용이 큼

<Aside type="tip" title="실전 감각">
llama.cpp의 `Q4_K_M`, MLC/ExecuTorch의 4bit 모델은 전부 **per-group weight-only 4bit** 계열임. 다음 레슨(KV cache)에서는 weight 말고 **KV cache 메모리**가 어떻게 병목이 되는지 봄.
</Aside>
