## 왜 필요한가

03번 레슨(#granularity-정확도와-가속-사이)에서 **무엇을**(단위, 기준) 지울지 정했다. 남은 질문은 세 가지다. (1) 전체 sparsity가 같아도 layer마다 얼마나 자르느냐에 따라 정확도가 크게 다른데, 그 비율을 어떻게 정하나. (2) 잘라낸 작은 네트워크를 처음부터 학습해도 되나, 아니면 꼭 큰 걸 먼저 학습해야 하나. (3) 0을 많이 만들었을 때 실제로 빨라지려면 하드웨어와 kernel이 무엇을 해야 하나. 세 번째를 모르면 "파라미터 90% 감소"가 latency로는 아무 의미가 없을 수 있다.

## 직관: 예산 나누기

```text
 같은 70% 삭감, 다른 배분

 uniform           layer A ███████░░░ 70%   (작고 민감: 정확도 -4.0)
                   layer B ███████░░░ 70%
                   layer C ███████░░░ 70%

 sensitivity 기반  layer A ░░░░░░░░░░  0%   (전체 파라미터의 1%뿐이라 안 잘라도 됨)
                   layer B ███████░░░ 70%
                   layer C ███████░░░ 71%   (크고 둔감: 조금 더 잘라도 괜찮음)
```

회사 예산을 모든 부서에서 똑같이 깎는 것보다, 깎아도 티가 안 나는 큰 부서에서 더 깎고 핵심 부서는 지키는 게 낫다. 각 부서가 얼마나 민감한지 재는 것이 sensitivity analysis다.

## 정식 설명

### 용어

**Pruning ratio (가지치기 비율)**: layer 하나에서 지우는 weight(또는 channel)의 비율. layer마다 다를 수 있다.

**Sensitivity analysis (민감도 분석)**: 다른 layer는 그대로 두고 layer 하나만 비율을 바꿔 가며 잘랐을 때 정확도가 어떻게 변하는지 재는 것.
*Measuring accuracy as a function of the pruning ratio of one layer at a time.*

**Lottery ticket (복권)**: 무작위 초기화된 큰 네트워크 안에 있는, 그 초기값 그대로 따로 학습하면 원래 네트워크만큼 정확해지는 작은 subnetwork.
*A sparse subnetwork that, trained in isolation from its original initialization, matches the full network's accuracy.*

**Iterative magnitude pruning (IMP)**: 학습 → magnitude로 일부 제거 → (초기값으로 되감기 또는 fine-tune) → 다시 학습을 반복하는 절차.

**Rewinding (되감기)**: 남은 weight를 학습 초기의 값으로 되돌리는 것. 원 논문은 0 step, 깊은 네트워크는 학습 초반 몇 step의 값으로 되감는다.

**Activation sparsity (activation 희소성)**: ReLU 뒤 activation에 0이 많은 성질. weight sparsity와 독립적으로 생긴다.

**Sparse Tensor Core**: NVIDIA Ampere 이후 GPU에서 2:4 sparse 행렬을 받아 dense 대비 2배의 수학 처리량을 내는 행렬 연산 유닛.

### Pruning 비율 정하기: sensitivity analysis

절차:

1. 학습된 모델에서 layer $\ell$ 하나만 비율 $r \in \{0.1, 0.2, \dots, 0.9\}$로 자른다 (03번 레슨(#criterion-1-magnitude)의 magnitude 기준). 다른 layer는 그대로.
2. fine-tuning 없이 validation 정확도를 잰다. layer마다 곡선 $\text{acc}_\ell(r)$을 얻는다.
3. 정확도 하락이 허용치(예: 1%p) 안인 가장 큰 $r$을 layer별 비율로 정하거나, 전체 목표 sparsity에 맞게 둔감한 layer부터 더 자른다.

곡선을 보면 보통 이렇다.

- **첫 layer**: 파라미터가 적고 입력에서 바로 feature를 뽑으므로 민감하다. 잘라도 얻는 게 적다.
- **큰 중간 layer, FC layer**: 파라미터가 많고 중복이 커서 둔감하다. 대부분의 삭감이 여기서 나온다.

한계: layer끼리의 상호작용을 무시한다(하나씩만 잘라 봤으므로). 그래서 정한 비율로 같이 자른 뒤에는 꼭 fine-tuning하고 다시 확인한다.

### 자동으로 정하기: AMC, NetAdapt

layer가 수십 개면 사람이 곡선을 보고 정하기 어렵다.

- **AMC (AutoML for Model Compression)**: 강화학습 agent가 layer를 하나씩 보며 비율을 고르고, 전체 FLOPs나 latency 제약을 만족하는 배분 중 정확도가 가장 높은 것을 찾는다.
- **NetAdapt**: 목표 latency를 조금씩 줄여 가며, 매 단계 "어느 layer를 잘라야 latency는 목표만큼 줄면서 정확도는 가장 덜 떨어지는가"를 실제 기기에서 잰 latency 표로 고른다.

둘 다 MAC 수가 아니라 **실제 latency**를 제약으로 쓸 수 있다는 점이 중요하다(02번 레슨(#지표끼리의-관계)).

### Lottery ticket hypothesis

03번 레슨의 순서는 "큰 모델 학습 → 자르기 → fine-tune"이었다. 그럼 잘린 작은 구조를 처음부터 학습하면 안 되나? 대개 무작위 초기화에서 작은 sparse 네트워크를 학습하면 정확도가 떨어진다. Frankle & Carbin(2019)은 다음을 관찰했다.

1. 큰 네트워크를 초기값 $\mathbf{w}_0$에서 학습해 $\mathbf{w}_T$를 얻는다.
2. $\mathbf{w}_T$에서 magnitude가 작은 $p\%$를 지워 mask $M$을 만든다.
3. 남은 weight를 **원래 초기값** $\mathbf{w}_0 \odot M$으로 되돌리고 다시 학습한다.
4. 2~3을 반복한다(IMP).

이렇게 찾은 subnetwork는 원래 네트워크와 비슷한 정확도까지 학습되지만, 같은 mask에 **새 무작위 초기값**을 넣으면 그렇지 못했다. 즉 mask만이 아니라 "mask + 그 초기값" 조합이 당첨 복권이다. 깊은 네트워크에서는 0 step이 아니라 학습 초반(전체의 수 % 지점)의 값으로 되감아야 잘 동작한다.

실용적 의미와 한계: 처음부터 작게 학습할 수 있는 subnetwork가 **존재한다**는 것을 보였지만, 그걸 찾으려면 큰 네트워크를 여러 번 학습해야 해서 학습 비용은 오히려 크다. 학습 초반에 ticket을 찾는 방법들이 후속 연구 주제다.

### Sparse 연산이 빨라지는 조건

일반 dense 행렬곱 하드웨어는 0을 건너뛰지 못한다. sparsity가 이득이 되려면 0을 **저장하지 않고, 읽지 않고, 계산하지 않아야** 한다.

**EIE (Efficient Inference Engine)**: FC layer의 행렬-벡터곱 $\mathbf{y} = W\mathbf{a}$ 전용 가속기.

- weight는 pruning + 4-bit weight sharing으로 압축해 **칩 안 SRAM**에 저장한다(01번 레슨(#에너지는-데이터-이동이-정한다)의 640 pJ DRAM 접근을 없앰).
- 열 단위 압축 형식(CSC)으로 저장해서 입력 $a_j$ 하나가 들어오면 $W$의 $j$번째 열에서 0이 아닌 것만 처리한다.
- 입력 activation이 0이면($a_j = 0$, ReLU 때문에 흔함) 그 열 전체를 건너뛴다.

그래서 연산량은 weight 밀도 × activation 밀도에 비례한다.

$$
\text{MACs}_{\text{sparse}} = \text{MACs}_{\text{dense}} \times (1 - s_W) \times (1 - s_a)
$$

**2:4 Sparse Tensor Core**: weight를 4개 중 2개만 남겨 절반 크기로 압축하고, 각 nonzero의 위치를 2-bit metadata로 저장한다. 행렬곱할 때 metadata로 입력에서 짝이 되는 원소만 골라 곱하므로 수학 처리량이 dense의 2배다(A100 FP16 기준 dense 312 TFLOPS, sparse 624 TFLOPS). 03번 레슨(#fine-grained-sparsity의-저장-비용)에서 본 대로 weight 저장은 dense의 0.5625배다.

**Roofline으로 보면** ([arch-foundations 21](/learning-website/arch-foundations/21-roofline-model/)):

- compute-bound(큰 batch, prefill): 수학 처리량이 2배라 최대 약 2배.
- memory-bound(batch 1 decoding): 시간이 weight 바이트에 비례하므로 최대 $1 / 0.5625 \approx 1.78$배.

## Worked example

### 예제 1. 같은 70%, 다른 배분

세 layer A, B, C의 파라미터가 10K, 400K, 590K(합 1M)이다. sensitivity analysis로 잰 정확도 하락(%p)이 다음과 같다(설명용 숫자).

| layer | 파라미터 | 50% | 70% | 90% |
|---|---|---|---|---|
| A | 10K | 1.0 | 4.0 | 15.0 |
| B | 400K | 0.1 | 0.3 | 2.0 |
| C | 590K | 0.0 | 0.2 | 0.8 |

목표: 전체 파라미터 70%(700K) 삭감. layer별 하락이 대략 더해진다고 근사한다.

- **Uniform 70%**: 하락 $4.0 + 0.3 + 0.2 = 4.5$%p.
- **A는 안 자름**: B 70%(280K), C는 남은 420K를 맡아 $420 / 590 = 71.2\%$. C의 하락은 70%와 90% 사이를 선형 보간해 $0.2 + \frac{1.2}{20} \times 0.6 \approx 0.24$. 합 $0 + 0.3 + 0.24 \approx 0.54$%p.

전체 삭감량은 같은데(700K) 하락이 8배 이상 작다. A는 전체의 1%라서 안 잘라도 잃는 압축률이 거의 없다.

### 예제 2. Weight와 activation sparsity가 곱해진다

FC layer $4096 \times 4096$, weight sparsity 90%, 입력 activation의 70%가 0(ReLU).

- dense MAC: $4096^2 = 16{,}777{,}216$
- 0이 아닌 weight와 0이 아닌 activation이 만나는 경우만: $16.78\text{M} \times 0.1 \times 0.3 = 503{,}316$
- 약 **33배** 적다. weight만 보면 10배, activation만 보면 3.3배인데 둘을 다 건너뛰는 하드웨어(EIE)면 곱으로 준다.

### 예제 3. 2:4를 LLM에 쓰면

7B 모델 FP16, batch 1 decoding. 이 상황은 memory-bound다([arch-foundations 22](/learning-website/arch-foundations/22-roofline-for-dl/#llm-prefill-vs-decode)).

- dense weight 14 GB → 2:4는 $14 \times 0.5625 = 7.875$ GB
- token 속도 상한은 weight 바이트에 반비례하므로 최대 $14 / 7.875 = 1.78$배
- 수학 처리량 2배는 memory-bound에서는 쓸모가 없다. 반대로 큰 batch의 prefill은 compute-bound라 2배 쪽에 가깝게 빨라질 수 있다.

## 코드

```python
import numpy as np

def spiral(n, rng):
    X, y = [], []
    for c in range(3):
        r = np.linspace(0.05, 1, n)
        t = np.linspace(c * 4, (c + 1) * 4, n) + rng.normal(0, 0.2, n)
        X.append(np.c_[r * np.sin(t), r * np.cos(t)]); y.append(np.full(n, c))
    return np.vstack(X), np.concatenate(y)

def forward(params, X):
    A = X
    for i, (W, b) in enumerate(params):
        Z = A @ W.T + b
        A = np.maximum(Z, 0) if i < len(params) - 1 else Z
    return A

def train(params, X, y, steps, lr=0.05, masks=None):
    params = [[W.copy(), b.copy()] for W, b in params]
    vel = [[np.zeros_like(W), np.zeros_like(b)] for W, b in params]
    for _ in range(steps):
        acts, A = [X], X
        for i, (W, b) in enumerate(params):
            Z = A @ W.T + b
            if i < len(params) - 1:
                A = np.maximum(Z, 0); acts.append(A)
        P = np.exp(Z - Z.max(1, keepdims=True)); P /= P.sum(1, keepdims=True)
        G = P; G[np.arange(len(y)), y] -= 1; G /= len(y)
        for i in reversed(range(len(params))):
            W, b = params[i]
            gW, gb = G.T @ acts[i], G.sum(0)
            if i > 0:
                G = (G @ W) * (acts[i] > 0)
            if masks is not None:
                gW = gW * masks[i]
            vel[i][0] = 0.9 * vel[i][0] + gW; vel[i][1] = 0.9 * vel[i][1] + gb
            W -= lr * vel[i][0]; b -= lr * vel[i][1]
    return params

acc = lambda p, X, y: (forward(p, X).argmax(1) == y).mean()

def magnitude_mask(W, s):
    k = int(round(W.size * s))
    if k == 0: return np.ones_like(W)
    th = np.sort(np.abs(W), axis=None)[k - 1]
    return (np.abs(W) > th).astype(float)

def apply(params, masks):
    return [[W * M, b.copy()] for (W, b), M in zip(params, masks)]

rng = np.random.default_rng(0)
X, y = spiral(200, rng); Xt, yt = spiral(200, np.random.default_rng(1))
sizes = [2, 128, 128, 3]
init = [[rng.normal(0, np.sqrt(2 / i), (o, i)), np.zeros(o)] for i, o in zip(sizes[:-1], sizes[1:])]
dense = train(init, X, y, 4000)
print(f"dense test acc = {acc(dense, Xt, yt):.3f}, weights per layer = {[W.size for W, _ in dense]}")

# 1) sensitivity analysis: layer 하나씩만 자르고 (fine-tune 없이) 정확도
ratios = [0.5, 0.7, 0.8, 0.9, 0.95]
print("\nlayer  size  | " + "  ".join(f"{r:.2f}" for r in ratios))
for L, (W, _) in enumerate(dense):
    row = []
    for r in ratios:
        masks = [np.ones_like(w) for w, _ in dense]; masks[L] = magnitude_mask(W, r)
        row.append(acc(apply(dense, masks), Xt, yt))
    print(f"  W{L}  {W.size:5d}  | " + "  ".join(f"{a:.3f}" for a in row))

# 2) 전체 weight의 80%를 지우는 두 가지 배분
total = sum(W.size for W, _ in dense)
def evaluate(alloc, name):
    masks = [magnitude_mask(W, s) for (W, _), s in zip(dense, alloc)]
    removed = sum(W.size * s for (W, _), s in zip(dense, alloc))
    print(f"{name:28s} ratios={alloc}  overall={removed / total:.3f}  acc={acc(apply(dense, masks), Xt, yt):.3f}")
print()
evaluate([0.8, 0.8, 0.8], "uniform")
evaluate([0.0, 0.83, 0.0], "sensitivity (W1 only)")

# 3) lottery ticket: 90% mask를 찾고, 그 mask로 처음부터 다시 학습
s = 0.9
M = [np.ones_like(dense[0][0]), magnitude_mask(dense[1][0], s), np.ones_like(dense[2][0])]
ticket = train(apply(init, M), X, y, 4000, masks=M)                    # 원래 init으로 되감기
reinit = [[rng.normal(0, np.sqrt(2 / i), (o, i)), np.zeros(o)] for i, o in zip(sizes[:-1], sizes[1:])]
random_init = train(apply(reinit, M), X, y, 4000, masks=M)             # 같은 mask, 새 init
Mr = [M[0], (rng.random(M[1].shape) >= s).astype(float), M[2]]
random_mask = train(apply(init, Mr), X, y, 4000, masks=Mr)             # 무작위 mask
print(f"\n90% W1, train from scratch:  winning ticket (mask + original init) = {acc(ticket, Xt, yt):.3f}")
print(f"                             same mask + new random init        = {acc(random_init, Xt, yt):.3f}")
print(f"                             random mask + original init        = {acc(random_mask, Xt, yt):.3f}")
```

```text
dense test acc = 0.998, weights per layer = [256, 16384, 384]

layer  size  | 0.50  0.70  0.80  0.90  0.95
  W0    256  | 0.997  0.990  0.857  0.663  0.533
  W1  16384  | 0.998  0.998  0.997  0.820  0.767
  W2    384  | 0.998  0.993  0.952  0.813  0.588

uniform                      ratios=[0.8, 0.8, 0.8]  overall=0.800  acc=0.883
sensitivity (W1 only)        ratios=[0.0, 0.83, 0.0]  overall=0.799  acc=0.995

90% W1, train from scratch:  winning ticket (mask + original init) = 0.998
                             same mask + new random init        = 0.998
                             random mask + original init        = 0.998
```

볼 포인트:
- **Sensitivity**: 가장 큰 layer W1(16,384개)은 80%까지 정확도가 그대로인데, 작은 W0(256개, 입력 바로 다음)은 80%에서 86%로, W2(384개, 출력 layer)는 95%로 떨어진다.
- **배분**: 전체 80%를 지울 때 모든 layer를 80%로 자르면 88.3%, 민감한 W0, W2는 두고 W1만 83%로 자르면 같은 80% 삭감으로 99.5%다. 예제 1과 같은 현상이다.
- **Lottery ticket**: 이 작은 문제에서는 세 경우 모두 99.8%로 차이가 없다. 문제가 너무 쉬워서 W1의 10%만으로도 어떤 초기값에서든 학습된다. lottery ticket 효과는 깊은 CNN처럼 sparse subnetwork를 학습하기 어려운 설정에서 나타난다. 작은 실험에서 효과가 안 보인다고 논문 결과를 부정하거나, 보인다고 일반화하지 않는 것이 중요하다.

예제 1과 코드처럼 layer별 배분에 따라 정확도 하락이 수 배 이상 차이 난다. 압축률을 보고할 때는 전체 sparsity뿐 아니라 layer별 비율도 같이 봐야 한다.
</Aside>

<Aside type="caution" title="Lottery ticket이 있으니 처음부터 작은 모델을 학습하면 된다?">
ticket은 큰 모델을 (여러 번) 학습해서 찾은 mask와 초기값이 있어야 쓸 수 있다. 무작위 mask나 새 초기값으로는 같은 결과가 보장되지 않는다. 학습 비용을 줄이는 방법이 아니라, 큰 네트워크 안에 좋은 작은 네트워크가 있다는 관찰이다.
</Aside>

<Aside type="caution" title="2:4 sparsity는 항상 2배 빠르다?">
2배는 수학 처리량의 상한이다. memory-bound 연산(batch 1 decoding)에서는 weight 바이트가 0.5625배라 최대 1.78배이고, metadata 처리와 kernel 효율 때문에 실제로는 그보다 작다. compute-bound인 큰 행렬곱에서 2배에 가까워진다.
</Aside>

## 서술형

### 문제. Pruning 계획 세우기

CNN 하나의 layer별 파라미터, MAC, sensitivity(fine-grained magnitude pruning, fine-tune 전 정확도 하락 %p)가 다음과 같다.

| layer | 파라미터 | MACs | 50% | 75% | 90% |
|---|---|---|---|---|---|
| L1 conv | 1K | 10M | 2.0 | 6.0 | 20.0 |
| L2 conv | 50K | 100M | 0.3 | 1.0 | 4.0 |
| L3 conv | 200K | 50M | 0.1 | 0.4 | 1.5 |
| L4 FC | 749K | 0.749M | 0.0 | 0.1 | 0.5 |

(a) 각 layer의 비율을 0, 50, 75, 90% 중에서 골라 전체 파라미터를 75% 이상 줄이면서 정확도 하락 합(더해진다고 근사)을 최소로 하라.

(b) (a)의 배분으로 MAC은 몇 % 줄어드나? 0을 건너뛰는 kernel이 있다고 가정한다. 파라미터 감소율과 비교해서 무엇을 알 수 있나?

(c) 이 모델을 sparse 연산을 지원하지 않는 휴대폰 CPU에서 빠르게 하는 것이 목표라면 (a)의 계획을 어떻게 바꿔야 하나? 어느 layer를 어떤 단위로 잘라야 하는지 설명하라.

<details>
<summary>풀이 보기</summary>

**(a)** 목표 750K 이상. 파라미터 대부분이 L4(749K)와 L3(200K)에 있다.

- L4 90%(674.1K) + L3 50%(100K) = 774.1K (77.4%), 하락 $0.5 + 0.1 = 0.6$
- L4 90% + L3 75%(150K) = 824.1K, 하락 0.9
- L4 75%(561.75K) + L3 90%(180K) = 741.75K, 75% 미달
- L4 90% + L2 50%(25K) = 699.1K, 미달

최선은 **L1 0%, L2 0%, L3 50%, L4 90%**, 하락 약 0.6%p.

**(b)** 줄어드는 MAC: L4 $0.9 \times 0.749\text{M} = 0.674\text{M}$, L3 $0.5 \times 50\text{M} = 25\text{M}$. 합 25.67M / 전체 160.75M ≈ **16%**.

파라미터는 77% 줄었는데 MAC은 16%밖에 안 준다. 파라미터는 FC layer에 몰려 있고 MAC은 conv layer(weight를 위치마다 재사용, 02번 레슨(#convolution-layer))에 몰려 있기 때문이다. 모델 크기가 목표인지 연산량이 목표인지에 따라 잘라야 할 layer가 다르다.

**(c)** sparse 연산이 없는 CPU에서는 fine-grained 0이 속도에 거의 도움이 안 된다. 그래서

- **channel pruning**으로 바꿔서 결과가 작은 dense layer가 되게 한다.
- latency가 목표이므로 MAC이 큰 **L2(100M)와 L3(50M)**를 먼저 줄인다. L2의 출력 channel을 자르면 L2와 L3의 MAC이 같이 준다(03번 레슨(#granularity-정확도와-가속-사이)의 연쇄).
- channel pruning은 같은 비율에서 정확도 손해가 fine-grained보다 크므로, 이 표가 아니라 channel 단위로 sensitivity를 다시 재야 한다. 비율은 MAC 대신 실제 기기에서 잰 latency를 기준으로 고르면 더 정확하다(NetAdapt 방식).
- L4는 파라미터는 크지만 MAC이 0.749M이라 latency에는 거의 영향이 없다. 모델 저장 크기가 문제면 L4는 fine-grained로 따로 줄이거나 quantization으로 줄인다.

</details>
